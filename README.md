# Практика № 2 — Несколько экспортёров через общий интерфейс

**Время:** 35 минут. **Уровень:** продолжающие.

## Сценарий
Бизнес-коду нужно экспортировать отчёты в старую консольную систему и в текстовый файл. Основной сценарий не должен зависеть от конкретной реализации.

## Задания
1. Изучите `ReportService`: объясните, почему он должен зависеть от `IReportExporter`.
2. Добавьте вторую реализацию `IReportExporter` — `TextFileReportExporter`.
3. Выбирайте реализацию в `Program`, не добавляя ветвление по типу экспортёра в `ReportService`.
4. Определите поведение при некорректном документе, пустом пути и ошибке записи.
5. Проверьте, что `ReportService` работает с обеими реализациями без изменения своего кода.
6. Добавьте тесты для обеих реализаций, пустого документа и ошибочного пути.
7. Дополнительно: объясните, как добавить JSON-экспортёр без изменения `ReportService`.

## Ограничения
- Не использовать пустой `catch`.
- Не добавлять `LegacyReportPrinter` в `ReportService`.
- Тесты должны использовать временные пути и удалять созданные файлы.
## Критерии готовности
- [ ] Есть две реализации интерфейса.
- [ ] `ReportService` не меняется при переключении реализации.
- [ ] Выбор реализации находится вне бизнес-логики.
- [ ] Ошибки записи не скрываются.
- [ ] Проверены минимум три сценария.
